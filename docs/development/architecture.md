# Widget architecture

`src/runtime/widget.tsx` coordinates Experience Builder/ArcGIS view lifecycle and cross-feature interaction. `src/setting/setting.tsx` owns builder configuration. Feature modules under `src/features/` own bounded resources and pure helpers; `src/components/` composes the viewer UI, `src/styles/` its styles, and `src/i18n/` presentation/localization.

Preserve foreground work priority, latest-request ownership, cancellation and view disposal. Native layers render bulk data; bounded overlays support feedback/selection. Ordinary image opening should not wait for optional complete route loading. Source organization alone does not establish runtime performance; measure in the host.

Runtime startup invalidates its pending work before unmount teardown. Deferred sprite preload and intro timers are cancelled; metadata requests and sprite chunking receive a startup abort signal. The injected override stylesheet is removed by its creating widget instance. Startup guards after module/username waits prevent late listeners, observers or DOM attachment.

Direct shared-view graphics and the widget's own coverage/detection layers are tracked by [OwnedMapResources](../../src/features/map-graphics/OwnedMapResources.ts). Weak sets mark exact instances without retaining retired graphics. Cleanup removes only registered resources, preserving unrelated graphics, same-ID layers and borrowed coverage layers. Feature controllers retain responsibility for their own overlays. Regression coverage lives in [resource ownership](../../tests/ownedMapResources.test.cjs) and [startup disposal](../../tests/startupDisposal.test.cjs).

Capture-route generation uses [RouteGeneration](../../src/features/routing/RouteGeneration.ts) to own one active run. Clearing/resetting a route, changing views, replacing analysis or route inputs, hiding/closing the widget, and teardown invalidate that run. Provider resolution, solves, preflights, graphics-layer loading and camera restoration check ownership before publishing results. An old run cannot clear a newer run's busy state or restore its camera. OSRM fetches and ArcGIS route requests receive the run's abort signal; travel-mode discovery that cannot be cancelled may finish, but cannot start a route solve after cancellation. This run-ownership layer does not alter optimization/scoring. See [generation regressions](../../tests/routeGeneration.test.cjs) and [provider cancellation regressions](../../tests/routingCancellation.test.cjs).

Detection tiles are owned by `DetectionLayerController`, with one bounded record per detection type. Its typed host supplies current view/settings, category selection/catalogs, source URLs, a layer factory, and loading/error callbacks. The widget retains React state, click/export selection, legacy feature-layer retirement and cross-feature coordination. Replacement/reset releases owned renderers; borrowed layers are not destroyed. Appearance updates reject late loads after replacement, disabling, view/map transfer or disposal. Direct [controller tests](../../tests/detectionLayerController.test.cjs) cover these contracts and the widget adapter; moved style/lifecycle logic is no longer tested by extracting large widget methods.

Pure capture-route scoring lives in [captureRouteScoring](../../src/features/routing/captureRouteScoring.ts): segment eligibility/priorities, corridor-expansion decisions, stop-owner mapping, anchor diagnostics, coverage-target deduplication and final summary totals. The widget supplies analysis/config snapshots and retains provider calls, cancellation, progress, logging and map writes. [Characterization tests](../../tests/captureRouteScoring.test.cjs) compare against [outputs from the original formula with an explicit neutral center weight](../../tests/fixtures/captureRouteScoring.baseline.json); `"NaN"` in that fixture represents JavaScript non-finite values.

Routing defaults now explicitly use a neutral `centerDistanceWeight` of 0, producing finite priorities without adding a center-distance preference. The optimizer reuses the existing 12m useful-segment threshold for both group length and weighted new-coverage value, and enforces the documented 40-candidate limit. Its local stop reason uses the shared result type, including `anchor-cap`. These are intentional configuration fixes after extraction: previously missing properties left scores non-finite and bypassed those filters/caps. [Routing default tests](../../tests/routingDefaults.test.cjs) exercise ranking, threshold boundaries, novelty filtering, candidate/selection limits, anchor rejection and time budgets.

Adaptive corridor orchestration lives in [adaptiveCaptureSelection](../../src/features/routing/adaptiveCaptureSelection.ts). It synchronously builds and selects local opportunities at each configured width, retaining the original expansion thresholds, stop-reason rules, log order and final-pass result. The widget forwards its current inputs and keeps toasts, progress, provider requests and generation cancellation. [Selection characterization tests](../../tests/adaptiveCaptureSelection.test.cjs) compare calls, logs, errors and results with the [previous widget loop](../../tests/fixtures/adaptiveCaptureSelection.baseline.json), including a real-optimizer case. This extraction adds no requests, timers or asynchronous work.

Final authoritative-solve batch pruning lives in [finalSolveBatchPruning](../../src/features/routing/finalSolveBatchPruning.ts). The synchronous helper returns calibration values, efficiency-ranked removals and survivors in baseline order without mutating its input. The existing 1–6 correction clamp, 0.96 reserve, 0.25-minute floors, stable ties and ID-based removal semantics are preserved. The widget retains budget/retry guards, provider solves, cancellation checks, diagnostics and the assignment of the active selection. [Characterization tests](../../tests/finalSolveBatchPruning.test.cjs) compare the helper through the actual widget adapter against the [previous calculation](../../tests/fixtures/finalSolveBatchPruning.baseline.json), including log order, boundary cases and deterministic varied batches. This extraction adds no network work or playback hooks.

OSRM generic preflight batch pruning lives in [preflightBatchPruning](../../src/features/routing/preflightBatchPruning.ts). Its local calculation retains the separate 0.85 preflight reserve, 1–6 calibration clamp, 0.25-minute floors, stable efficiency ties and ID-based removals. The widget still owns network-specific and near-budget single-removal branches, provider calls, cancellation checks, the no-removal break, anchor/owner rebuilds and existing diagnostics. [Characterization tests](../../tests/preflightBatchPruning.test.cjs) compare the calculation and actual widget adapter with the [previous block](../../tests/fixtures/preflightBatchPruning.baseline.json), including the no-removal path and rebuild/log ordering. This stage adds no network requests or playback work.

Preflight anchor/leg construction lives in [preflightDiagnostics](../../src/features/routing/preflightDiagnostics.ts). Snap diagnostics retain endpoint exclusion, owner lookup by capture-owner count, rounding to one decimal before filtering/ranking and stable ties. Leg diagnostics retain longitude/latitude argument order, missing-coordinate fallback, metre/two-decimal rounding, and a top-ten copy that does not reorder the full leg list. These rounded leg values feed the existing main quality gate, so their precision is behavioral. The widget still owns rejection thresholds, quality predicates, logging, provider calls and cancellation. Trial-probe quality checks elsewhere use raw values; this stage does not unify them. [Tests](../../tests/preflightDiagnostics.test.cjs) compare actual widget adapters, outputs and distance-call order against the [previous construction](../../tests/fixtures/preflightDiagnostics.baseline.json).

The three trial-probe internal-traversal checks share [trialPreflightQuality](../../src/features/routing/trialPreflightQuality.ts). It checks only same-owner internal legs against raw 450m/4.5min thresholds, skips endpoints/unknown owners/missing coordinates and short-circuits on the first failure. It intentionally does not use the rounded main-preflight diagnostics. Provider awaits, run checks, replacement-specific snap checks, logging and candidate acceptance stay in the widget. [Characterization tests](../../tests/trialPreflightQuality.test.cjs) compare all three actual adapters with their [previous predicates and request-to-evaluation blocks](../../tests/fixtures/trialPreflightQuality.baseline.json), including provider failures and cancellation before quality evaluation.

Replacement-pair construction lives in [replacementPairRanking](../../src/features/routing/replacementPairRanking.ts). It excludes active/rejected/nonpositive additions, caps addition/removal candidates at five before pairing, requires gains above 25, preserves existing anchor accounting, ranks by gain then baseline gap with stable ties, and returns at most five probe pairs. The widget retains pass limits, ordered trial-stop construction, provider calls, cancellation and acceptance. [Tests](../../tests/replacementPairRanking.test.cjs) compare actual adapter output against the [previous ranking block](../../tests/fixtures/replacementPairRanking.baseline.json), including pre-pair caps, strict thresholds, capacity boundaries, identity and pass-limit behavior.

Network-penalty attribution and candidate scoring live in [captureNetworkPenalties](../../src/features/routing/captureNetworkPenalties.ts). It preserves the adaptive 2–4 minute threshold, rounded diagnostic inputs, full versus split owner attribution, sentinel exclusions, cleanup-mode endpoint/pathological-owner rules, the 100m value floor and stable two-key ranking. It returns all ranked candidates; downstream probe/removal caps, provider calls, run checks and UI stay in the widget. [Tests](../../tests/captureNetworkPenalties.test.cjs) compare maps, map insertion order and actual widget adapter outputs against the [previous calculation](../../tests/fixtures/captureNetworkPenalties.baseline.json), including edge cases and the singleton guard.

Near-budget winner comparisons live in [budgetProbeComparison](../../src/features/routing/budgetProbeComparison.ts). Network and fitting probes retain the 0.25-minute relief floor, strict cost improvement beyond 0.5, and within-0.5 tie preference for higher extra time. Generic progress retains the strict 0.1-minute improvement and earliest equal-time winner. Returned record shapes remain distinct so existing logs and fallback selection do not change. The widget owns quality/fit gates, provider requests, run checks, fitting-over-progress preference and one-removal fallback. [Tests](../../tests/budgetProbeComparison.test.cjs) compare all three actual adapters against the [previous blocks](../../tests/fixtures/budgetProbeComparison.baseline.json), including sequential and generic-gate behavior.

Adaptive network-removal planning lives in [adaptiveNetworkRemoval](../../src/features/routing/adaptiveNetworkRemoval.ts). It preserves removal limits of 1/2/4/6 at overrun ratios 1.4/2/3, candidate order, ID-set cardinality and repeated entries for duplicate-ID diagnostics. The widget retains logs, quality-cleanup permanent rejection, survivor sorting, stop/owner rebuilds and break/continue control flow. [Tests](../../tests/adaptiveNetworkRemoval.test.cjs) compare actual planning/application adapters against the [previous block](../../tests/fixtures/adaptiveNetworkRemoval.baseline.json), including all thresholds, minimum retention, cleanup and retry/fallthrough behavior.
