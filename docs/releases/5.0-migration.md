# Prepare an existing app for 5.0

This guide describes the development candidate. Check the final release notes and supported host matrix before updating a production app. [Changelog](../../CHANGELOG.md)

1. **Record the current deployment.** Save the widget artifact, experience configuration, host version, and service settings. Inventory any notes and regional Places data your deployment already uses.
2. **Choose the target host.** Start with a fresh Developer Edition 1.21 host and follow the documented pnpm installation. Keep the existing app and widget available while testing the new copy. [Host migration](../installation.md#move-an-existing-app-to-121)
3. **Install the complete widget.** Include bundled assets. Confirm your Map widget binding, visual settings and routing configuration before changing optional services. [Install and launch](../installation.md)
4. **Review optional services.** Keep your intended Places source. Existing external URLs without a source selector are supported by the source-selection rules. Review Enterprise note capabilities and workspace migrations with the operator before changing shared records. [Places architecture](../development/places-architecture.md#portal-source) · [Workspace operations](../../tools/community-notes/README.md)
5. **Verify and publish.** Run the live matrix in a copy of the app, including real viewer permissions and mobile layout. Use the prior artifact and saved configuration if the deployment must roll back. Coordinate database rollback with the operator. [Acceptance](../development/exb-1.21-validation.md) · [Publishing](../publishing.md)

The development manifest uses major/minor/patch version numbers. Document required actions and compatibility changes in the changelog. This checkout does not establish support windows or removal dates. The maintainer records those decisions for the published release.
