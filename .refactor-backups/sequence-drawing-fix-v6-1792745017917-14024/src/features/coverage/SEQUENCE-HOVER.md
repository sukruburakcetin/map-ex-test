# Sequence highlights

The Turbo base coverage layer stays unchanged when selection or hover changes. Highlighting never calls its `loadStyle`, edits its style layers, replaces its reference or removes it from the map. Coverage filter changes and view initialization still legitimately load a base style.

`TileSequenceHighlights.ts` owns selected and hovered identities. Blue selection and neon green hover remain independent. Hover is a line only (`#00ff88`, width 6); selected lines and circles use blue with their original dimensions, opacity and white circle outline. Neither path connects API image coordinates to invent a main-map route.

In MapView, selected/hovered geometry is decoded from the original Mapillary sequence/image tile features. The existing raw-tile cache is reused. Decoding yields to the event loop, respects cancellation, and retains at most 64 sequence/tile entries and 100,000 vertices. Buffered line geometry is clipped at tile boundaries; buffered points use their canonical tile only. The measured native coordinate adjustment is applied to presentation geometry. Dimensions convert CSS pixels to ArcGIS symbol points. Capture date, quality, ownership, pano, travel and zoom filters follow the original native styles. Two persistent GraphicsLayers reuse Graphic instances. Selection and hover have independent jobs, signatures, cancellation and graphic collections: a hover refresh cannot replace or shrink the displayed blue selection. Viewport extensions keep existing fragments until the remaining tiles finish, then remove retired fragments once. A different target or mouseout clears only the affected role. Same-sequence geometry producers are shared with separate subscribers, so cancelling one role leaves the other alive. Image opening and viewport callbacks refresh hover independently while selected work is deferred. Late work cannot commit over a newer target or view.

SceneView rasterizes native tile styles onto terrain; ordinary screen-sized graphics did not match the native symbols' scale and softness in controlled rendering. `NativeTileHighlightCache.ts` therefore creates fixed native styles filtered to one sequence and one role. These layers are never restyled after creation. The two most recent selections and two most recent hover targets are retained and shown/hidden for reuse; older layers are removed and destroyed. At most four highlight renderers remain attached, with at most two visible. Native paints, layout, zoom limits and filters are copied, with only blue selection color or the intentional green hover width/color changed. A first visit to an uncached sequence can still take time to render its highlight, while the base coverage stays visible. Recent targets reuse their renderer.

All overlays sit above base coverage and below interactive sign/object layers. View transfer, filter rebinding and widget cleanup cancel work, destroy highlights and release geometry caches. Base coverage keeps its logical selection-anchor identity.

Overlaying translucent blue on the unchanged green base slightly changes the final blended opacity. Native dimensions and configured alpha are retained; this is the tradeoff for leaving the base renderer untouched. MapView uses crisp graphics; SceneView retains the SDK's native terrain rasterization.

The older `NativeSequenceSelection`, `SequenceHoverHighlight` and `PreparedVectorTileLayer` modules remain for compatibility/regression coverage of earlier installers; the widget no longer uses their style-renewal path.

## Image-first clicks

Native point decoding and the spatial index carry Mapillary's `sequence_id` through the picked point and frozen click anchor. Known native image clicks and green sequence hover therefore need no Graph request to recover sequence identity. Tooltip metadata stays optional; malformed/missing source identity keeps its existing fallback.

An exact hovered image starts `moveTo` before a separate coordinate query or route preparation. Tracking switches identity through constant-time `beginSelection`, retaining same-sequence complete-route indices. The same immutable route snapshot is never traversed/reindexed for a repeated click. A different sequence's cached full route is adopted after the image opens. Coordinates come from the viewer image when available. Viewer callbacks cannot start local ID/coordinate enumeration while opening or while cached context is being adopted. Blue selection work is deferred while the image opens. Once opened, image-loading state clears independently of optional map/route metadata. Stale viewer events cannot cancel a newer click. Regional line clicks still resolve the nearest image ID first. Image download/decode latency remains dependent on Mapillary.

## Secondary work

`TimeTravelAvailability` shares the current image's pending check and successful result. Different images/tokens and cleanup cancel obsolete chains; failed checks remain retryable. Viewer events cancel old work without starting a new query for every playback frame; secondary checks retain the existing 300 ms scheduling. Both request stages honor cancellation.

`CachedSequencePreview` coalesces pending/completed optional previews by selection, view and immutable tile-buffer references. Replacing a tile invalidates the preview; superseded jobs cannot commit. Turbo previews skip scanning/decoding while no minimap consumes them, and opening a minimap requests the current preview. Legacy main-map preview behavior is retained. One snapshot/job is retained and released on cleanup.

Tests cover geometry, filters, independent role cancellation, cache reuse and eviction, native style fidelity, cleanup, image/metadata ordering, large warm-route traversal avoidance, background request deduplication and stale-click guards. Controlled Chromium checks use real ArcGIS MapView/SceneView with synthetic tiles, including repeated targets and stable base-layer identity. Live portal terrain/data require validation in the authenticated application.
