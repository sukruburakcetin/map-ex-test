# Elevation profile

`ElevationProfileController` builds the ArcGIS profile input and an immutable frame-distance index from the same ordered sequence snapshot. Segment distances use the SDK's geodesic calculation in metres, in bounded batches. Identical inputs are reused; image playback does not regenerate profiles or scan the sequence.

`profileIndicator.ts` renders a small SVG chart from the public `ElevationProfileLine.samples` API. Its explicit distance axis positions the dashed blue current-image line. The frame label includes its ordinal, distance, source-labelled computed/reported camera altitudes and an image-ID tooltip. Distance-axis zoom, pan and reset use the chart buttons. All elevations and stored distances are metres; long horizontal axes are labelled in kilometres.

Only confirmed viewer image events may drive the current-image line. An optimistic selection, missing frame, or mismatching route/viewer hides the line. A separate grey line and “Inspecting profile” text show interpolated sample values under the pointer. Inspection neither changes imagery nor navigates the map. ArcGIS's sample-snapped map visualizations are disabled, leaving the existing green active-image marker authoritative.

The SDK still owns terrain queries, loading progress, profile visibility switches and statistics. Its native chart is disabled through `visibleElements.chart: false` so a second chart is never initialized. The renderer expands the SDK main wrapper to its content height and restores that local layout override during cleanup. Distance ticks adapt to panel width. Frame changes do not rebuild paths; sample refinement redraws are coalesced to at most 10 Hz. Resize handling ignores height-only changes, and SDK status/legend DOM mutations do not invalidate chart geometry. The renderer does not use private chart internals, arbitrary SVG paths, screenshot readback or predicted frames. Sample rendering preserves missing-data gaps and bounds SVG complexity by chart width.

Route replacement and view transfer remove the old chart, watch, widget and fallback terrain source. The controller removes widgets from their creating view. The elevation profile never changes the visible map's Ground; the independent 3D-terrain setting owns optional scene terrain.

Camera height sources are preserved independently by `imageAltitudeFields`: `computed_altitude` becomes `computedAltitude`, and `altitude` becomes `reportedAltitude`. The renderer plots separate orange/purple curves with independent visibility controls. Missing or invalid values are gaps; legitimate zero and negative heights are retained. Ambiguous legacy `alt` values are not plotted. These are camera-height estimates, not surveyed road/bridge elevations; no terrain substitution or bridge flattening is applied.

Camera curves use the frame index directly instead of an SDK input profile, so no extra terrain-based camera query is generated. Terrain/infrastructure queries receive a horizontal polyline without synthetic Z=0 values. Coordinate caches use the `height-v2:` namespace and mark downloaded records with `heightDataVersion: 2`; old combined-height caches receive a one-time metadata refresh, then normal bounded RAM/IndexedDB reuse resumes. Existing imagery preview caches and field notes are untouched.
